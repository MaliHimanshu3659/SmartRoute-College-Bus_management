1. Project Title & Introduction

1.1 Project Title

SmartRoute: Intelligent College Bus Management & Dynamic Attendance System

1.2 Executive Summary

Efficient student transportation is a crucial logistical backbone for educational campuses. Traditional college transit management frequently relies on manual student manifests, fixed bus schedules that ignore day-to-day attendance variations, and vocal roll-calling. These antiquated procedures result in prolonged travel delays, high fuel consumption caused by stopping at deserted locations, and frequent attendance discrepancies.

SmartRoute is a comprehensive, production-tested web platform engineered to modernize college transit. It enables three core personas—Students, Bus Drivers, and Campus Administrators—to coordinate in real time. The platform provides interactive Leaflet.js stop navigation, daily commute availability declarations, smart route optimization that pinpoints which bus stops can be skipped when zero riders are registered, and a secure attendance verification system utilizing cryptographically generated 60-second expiring dynamic QR codes.

1.3 Relevance to Web Development Syllabus

  • Module 1 (Semantic HTML5): Accessible web page structure, forms, tables, canvas elements, and semantic tagging without proprietary frameworks.

  • Module 3 (JavaScript Fundamentals & DOM): Event-driven architecture, form validation, dynamic DOM rendering, and client-side state manipulation.

2. Problem Statement & Objectives

2.1 Problem Statement

University transit fleets face multiple operational bottlenecks on a daily basis:

  1. Wasted Fuel and Idle Driving: Fleet buses routinely travel to every scheduled stop along an expansive route, even when enrolled students are absent, causing unnecessary fuel expenditures, carbon emissions, and transit delays.
  2. Manual & Inaccurate Attendance: Drivers attempting to manually record paper attendance while navigating dense city traffic creates severe safety hazards and inaccurate records.
  3. Proxy Attendance Vulnerabilities: Static barcodes or physical ID cards allow unauthorized students to clock in for absent peers or share static QR screenshots.
  4. Information Asymmetry: Students lack visibility into whether their designated bus has departed, which stops have been serviced, or when they are expected at the pickup point.

2.2 Project Objectives

The primary engineering objectives of SmartRoute are:

  • Dynamic Daily Commute Declaration: Provide students with an intuitive daily toggle ("Will you use the bus today?") that locks at departure time and informs the system of active pickups.
  • Active Stop & Empty Stop Differentiation: Automatically aggregate daily declarations so drivers clearly see which stops have waiting students and which stops have zero riders and can be safely bypassed.
  • Cryptographic Time-Expiring QR Code Attendance: Generate dynamic QR tokens on the driver's display that refresh every 60 seconds and are verified against server-side SHA-256 hashes, eliminating screenshot sharing and proxy marking.
  • Real-Time Route & Fleet Visualization: Deliver lightweight OpenStreetMap and Leaflet.js interactive maps for students and drivers showing pickup coordinates and transit trajectories.
  • Role-Based Access Control (RBAC): Guarantee secure session authorization with distinct dashboards tailored exclusively for Students, Drivers, and Administrators.

4. System Design & Architectural Overview

4.1 High-Level Architecture

SmartRoute adopts a 3-tier client-server architectural paradigm comprising a Presentation Layer, an Application / Business Logic Layer, and a Relational Data Persistence Layer.

4.2 Dynamic QR Verification Workflow

  1. Session Initialization: Upon driver departure, the driver console calls POST /api/driver/qr/generate.
  2. Cryptographic Token Creation: The backend generates a 32-byte cryptographic random string, creates a SHA-256 hash, and inserts the record into attendance_sessions with expires_at = NOW() + 60s.
  3. Display & Refresh: The plaintext token is converted to a high-resolution QR matrix displayed on the driver's dashboard, with a visible countdown timer.
  4. Student Scan & Submission: The student opens their dashboard, clicks "Scan QR Attendance", grants camera access via the HTML5 MediaDevices.getUserMedia() API, and transmits the decoded token to POST /api/student/scan-attendance.
  5. Verification & Record Creation: The server computes the SHA-256 hash of the received token, validates that expires_at > NOW() and is_revoked = 0, checks the uniqueness constraint for the day, records the verified attendance record, and returns a verified JSON response.

6. Implementation Details & Web Technology Stack

6.1 Frontend Implementation

  • Semantic HTML5 Structure: Standards-compliant documents using <header>, <nav>, <main>, <section>, and <footer>. Forms are enhanced with client-side regex validations, accessible labels, and input types (tel, email, password).
  • Responsive CSS3 & Bootstrap 5: Clean UI system based on custom CSS custom properties (--primary, --navy, --amber-bg), utilizing CSS Flexbox and 12-column Grid systems for responsive layouts across mobile phones, tablets, and desktop displays.
  • Interactive Mapping with Leaflet.js: Lightweight OpenStreetMap rendering with customized bus stop pin markers, popup modals, and vehicle tracking icons without external proprietary API keys.
  • Native AJAX & Fetch API: Standardized client-side API abstraction module (client/js/api.js) featuring reusable get(), post(), and del() wrappers handling JSON serializations, HTTP credentials, and error banners.
  • QR Code Scanning Engine: In-browser camera decoding powered by html5-qrcode, granting instantaneous mobile scanning without native app installations.

6.2 Backend & REST API Implementation

  • Node.js & Express.js: Modular, layered architecture cleanly dividing routes (/api/auth, /api/student, /api/driver, /api/admin, /api/tiles) from controllers and data access services.
  • Session Authentication & Security: Built with express-session and express-mysql-session storing sessions in MySQL. Protected with helmet security headers and HTTP-only cookies.
  • Cryptographic Password & QR Hashing: Passwords hashed with bcryptjs (salt rounds 10). Dynamic QR tokens generated with crypto.randomBytes(32) and validated against crypto.createHash('sha256') digests with a strict 60-second database expiration window.
  • Map Tile Proxying & Caching: High-performance tile proxy controller (server/src/controllers/tiles.controller.js) that caches OpenStreetMap PNG tiles locally in os.tmpdir() with HTTP 304 caching headers, avoiding upstream rate limits and EROFS read-only filesystem errors in cloud serverless deployments.

9. Conclusion & Future Enhancements

9.1 Project Outcomes & Conclusions

SmartRoute successfully demonstrates the practical implementation of end-to-end full-stack web engineering principles as prescribed in the Web Development curriculum. Key project achievements include:

  • Elimination of Static Paper Roll-Calls: Replaced vulnerable physical sign-in sheets with a cryptographically enforced, 60-second dynamic QR code attendance system.
  • Actionable Fleet Route Optimization: Drivers receive live stop occupancy data, preventing redundant detours to deserted stops and decreasing trip transit times and fuel waste.
  • Production Cloud Deployment: Configured for high-speed serverless deployment on Vercel Edge networks with static asset caching, clean routing rewrites, and support for remote cloud MySQL clustering.
  • Open Standards Architecture: Built using standards-compliant HTML5, CSS3, ES6 JavaScript, Express.js, and normalized MySQL without proprietary framework bloat.

9.2 Future Enhancements

To further extend the capabilities of SmartRoute in subsequent iterations, the following roadmap is proposed:

  1. Automated IoT GPS On-Board Trackers: Integrate Raspberry Pi / ESP32 OBD-II telemetry hardware directly into bus cabins to transmit automated vehicle coordinates without requiring a driver smartphone screen to remain awake.
  2. Parent & Student SMS Notifications: Integrate Twilio or Firebase Cloud Messaging (FCM) to push automated arrival notices when the bus is within a 2-kilometer geofence of the student's designated stop.
  3. Machine Learning Route Optimization: Analyze historical monthly attendance patterns with predictive clustering models (e.g. DBSCAN or K-Means) to dynamically re-sequence bus routes based on day-of-the-week attendance trends.
  4. Offline Attendance Caching (PWA): Implement Service Workers and IndexedDB client storage to allow offline attendance marking in low-cellular college transit corridors, syncing automatically upon network re-establishment.
